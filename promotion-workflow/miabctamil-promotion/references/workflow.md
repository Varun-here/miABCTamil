# Operating modes

## Weekly content

Input: week, goal, audience, channels, source materials, CTA. If omitted, propose three posts across seven days, split between parents and adult beginners, plus one short video script. Leave dates unscheduled until a week is established. Do not invent an app URL.

Deliver a calendar with asset ID, date, audience, channel, purpose, format, source IDs, CTA, draft path and review status. Provide complete Tamil and English captions, parent-facing explainer copy and scene-by-scene short video scripts. For video scripts include duration, visual, narration and on-screen text. Match language naturally instead of translating word for word. Keep source-dependent claims separate until resolved.

## Outreach

### Interactive intake when the run starts

Owner preference: ask for email-drafting details during an outreach run, not while discussing or configuring the workflow. When the owner starts an outreach request, first collect missing recipient name/role/organization, sender name/role, desired next step, previous contact or relevant exchange, supporting facts/links/attachments, and language/tone. For investor outreach, request approved SAFE details only when relevant. Reuse facts already supplied; do not ask the same questions again. An email address is optional for drafting. Present a concise grouped intake and wait for the owner's response before drafting recipient-specific copy. If the owner explicitly requests a generic example or templates, provide those without forcing intake. Once the owner answers, draft using the available facts and identify any essential unresolved details; never invent them. This intake applies only to outreach, not the content or asset workflows.

Input: recipient list, segment, relationship history, objective, sender identity, supporting sources. Segments: schools, education journalists, Tamil diaspora parent groups, investors. For each requested recipient, deliver a cold version and a warm follow-up variant, subject lines, concise message and one next step. Label the warm version conditional if there is no actual prior contact. Never invent familiarity, names or recipient interests. Use supplied personalization; research only when requested/needed and available, with sources.

Use a goal-based compose process directly in chat. A tool named message_compose is optional, not a dependency. Investor drafts use only the supplied deck and verified round terms. School outreach must not imply Karunya endorsement. Contact lists and private investor material stay in the local workspace unless the owner asks to share them.

Distinguish cold introductions, follow-ups to unanswered messages, and warm follow-ups after an actual exchange. Use prior replies or meeting notes for warm personalization; an unanswered cold message alone does not establish a relationship. For each recipient, record the goal, source for the personalized detail, relationship basis and exact draft version outside the message body. In the original workspace, the outreach intake and additional variants are in runs/2026-09-15-outreach/.

## Assets

When configuring or running the asset generator, read [assets.md](assets.md). It defines source intake at run time, actual DOCX/PPTX creation, video capability checks, testimonial attribution/permission, verification and deliverables. Ask for the relevant materials when an asset run starts, not during configuration.

Turn supplied deck/market analysis into an editable DOCX one-pager or PPTX mini-deck, using the available Documents or Presentations skill. Preserve market date, geography and source definitions. A one-pager normally has audience problem, demonstrable product experience, supported evidence and one CTA. A mini-deck may add product walkthrough and next steps. Do not build fictional evidence sections just to fill a layout.

For Tamil Sounds Module demos, use actual screenshots/recordings or accessible app flow. Deliver timed storyboard, bilingual narration, on-screen text and shot list; create a rendered video only with adequate source footage and a working rendering tool. Clearly report whether the output is a script, storyboard or playable video.

For testimonials, use verbatim supplied quotes with approved attribution and public-use permission. Do not present assistant-written paraphrases as authentic quotes. Without approved testimony, produce an interview/request template and identify what remains needed.

## Tracking and learning

For tracking updates and results reviews, read [tracking.md](tracking.md). It defines run-time intake, event mapping, duplicate prevention, outcome handling and campaign-specific analysis. The owner's quick guide is TRACKING.md in the working folder.

Use `miABCTamil-Tracker.xlsx`. Read the latest workbook before editing; use the Spreadsheets skill when available. Outreach has one row per recipient per campaign. Keep stable Record IDs. Follow-ups update the same row's last-sent date, next follow-up and notes; do not duplicate the recipient and inflate conversion totals.

Enter confirmed dates and Yes/No outcomes only. Blank means unmeasured/unknown; No means checked with no outcome as of the recorded Checked date. A conversion requires the owner-defined event in Conversion definition. Keep a sent date before measuring a reply/conversion. The summary reports only entered records, all campaigns combined, with rates among sent rows whose outcome is known. It does not claim delivery rates or causation.

Prepared rows end at 210. Extend table, formulas, validation and formatting together before exceeding the capacity. Do not change formulas into fixed values. Calendar rows carry stable asset IDs, dates, audience, format, language review, owner review, sources and artifact locations. Store full copy in run files, not huge cells.

On a results request: summarize sent, measured coverage, replies, conversions and rates; separate segment/cohort comparisons using the same observation window. Explain missing coverage and small samples, then propose one useful experiment. Do not attribute a conversion to outreach without supporting evidence.

## Finish each run

Return file links, a short summary of deliverables, and specific missing inputs. Record completed outputs, source IDs, pending reviews and next step in SESSION-STATE.md. Review status does not block creation of requested draft files. Never imply automatic weekly execution or background publishing.
